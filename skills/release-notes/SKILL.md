# Release Notes Skill

When writing release notes, always follow this structure:

1. **Highlights** — the 3 most exciting changes, one line each, written for users
   (not engineers). Start each with an emoji.
2. **New features** — bullet list, each with a one-line "why it matters".
3. **Fixes** — bullet list, plain language.
4. **Upgrade notes** — anything the user must do, or "nothing to do".

Rules:
- Never invent version numbers or dates — ask or omit.
- Keep the whole thing under 250 words.
- Tone: friendly, confident, no jargon.
